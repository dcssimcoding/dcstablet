DCS Tablet

DCS Tablet shows two aircraft displays on your tablet. You can touch their buttons to operate the same buttons in DCS World.

Initial aircraft support is for the F-18 only: the DCS F/A-18C Hornet.

Version: 0.1.1. Status: development version. Earlier builds passed live DCS cockpit checks for video, touch controls, reconnection, and normal-exit display restoration. The safety patch has its own validation record in Test record. An earlier build also passed a user-reported iPad Safari test; Safari has not been retested after the latest changes. Extended tablet tests and a complete DCS flight test are still necessary.

What you need for a flight

  • A Windows 10 or Windows 11 x64 PC with DCS World installed.
  • The Microsoft Visual C++ v14 x64 Redistributable.
  • Windows Media Foundation. Windows N editions need the Media Feature Pack.
  • The DCS F/A-18C Hornet module for a flight.
  • A tablet with a web browser.
  • A private home network for both devices.
  • A virtual display for a flight.

The demo does not need DCS World or a virtual display. The Windows package does not need a Rust or Python installation.

Start here

Download Windows 0.1.1, then follow the user guide. Before setup, read Data safety and keep a separate backup of your normal Saved Games profile. After extracting the Windows package, you can also open START-HERE.html for the complete offline guide.

Example: The demo shows two colored test displays. It does not show a live aircraft.

Important connection information

DCS Tablet has no password or tablet approval step. A device with network access to the application can request a connection. A connected viewer can operate the DDI buttons during a flight.

Use DCS Tablet only on a private network with devices that you trust. Do not make the application available through your router's port forwarding settings.

The application uses HTTP for its page and control messages. WebRTC encrypts the video connection. Network connection gives the setup instructions and the limits of this protection.

User guide

This guide is for DCS Tablet 0.1.1. Initial aircraft support is for the DCS F/A-18C Hornet (F-18) only.

Complete the tasks in the order given. Each task gives a result.

Before you start

Use Windows 10 or Windows 11 x64. The application uses the H.264 encoder supplied by Windows Media Foundation. Windows N editions need the Media Feature Pack. Install that feature through Windows settings before you start the demo.

Install the Microsoft Visual C++ v14 x64 Redistributable if it is absent. Use Microsoft's runtime download instructions. The application needs the runtime, not Visual Studio or the C++ Build Tools. DCS Tablet does not include a runtime installer or a codec DLL.

1. Prepare the application folder

Before you start, download the Windows release ZIP from DCS Tablet Releases. The file name for this version is dcs-tablet-0.1.1-windows-x64.zip. The GitHub Source code ZIP does not contain the application file.

  1. Create a folder named DCS Tablet on your desktop.
  2. Right-click the release ZIP.
  3. Click Extract All.
  4. Select the desktop DCS Tablet folder as the destination.
  5. Click Extract.
  6. Open the DCS Tablet folder.
  7. Make sure that the folder contains dcs-tablet.exe and Start-Demo.cmd.

Result: The application files are in the desktop DCS Tablet folder.

Example folder:

Desktop
  DCS Tablet
    dcs-tablet.exe
    Start-Demo.cmd
    Start-DCS-Tablet.cmd
    Restore-Display.cmd
    START-HERE.html
    docs
    scripts

Keep these files together. Do not start the application from inside the ZIP.

2. Prepare the network

  1. Connect the PC to your home network.
  2. Connect the tablet to the same network.
  3. Complete Network connection.

Result: Windows permits the tablet to communicate with DCS Tablet. The PC can use an Ethernet cable while the tablet uses Wi-Fi. Both devices must use the same local network.

3. Do the demo test

The demo uses colored test displays. Its aircraft buttons do not operate.

  1. Open the application folder on the PC.
  2. Double-click Start-Demo.cmd.
  3. Keep the new console window open.
  4. Find the address after LAN: in that window.
  5. Hold the tablet with its long side horizontal.
  6. Open the tablet's web browser.
  7. Enter the PC address in the browser's address bar.
  8. Tap Connect.

Example console address:

LAN: http://192.168.1.20:8090/

For this example, enter http://192.168.1.20:8090/ on the tablet. Your PC address can be different. Do not use this example address unless it agrees with your PC address.

Result: Two colored displays show moving lines. The page shows DEMO and Demo · controls disabled. The page also shows the application version and build date.

If the page does not open, use the problem guide.

4. Stop the demo

Stop the demo before you start a DCS Tablet flight.

  1. Tap Disconnect on the tablet.
  2. Click the demo console on the PC.
  3. Press Ctrl+C.
  4. If Windows asks Terminate batch job, enter Y.
  5. If the console asks for a key, press Enter.

Result: The demo stops. Its network address is available for the flight application.

5. Prepare the virtual display

  1. Complete Virtual display.

Result: Windows has a virtual display with a 1024 × 512 display mode. The physical monitor remains the main display.

The virtual display supplies space for DCS to draw both DDIs. It does not require another physical monitor.

6. Open PowerShell in the application folder

PowerShell is a Windows application for text commands. You use it for the first setup. Normal flights use a command file that you can double-click.

  1. Open the application folder in File Explorer.
  2. Click the File Explorer address bar.
  3. Enter powershell.
  4. Press Enter.

Result: A PowerShell window opens in the application folder. The end of its folder address shows DCS Tablet.

For each command in this guide:

  1. Copy the complete command line.
  2. Paste the line into PowerShell.
  3. Press Enter.

Do not copy the code block's label, such as powershell.

7. Prepare the DCS profile

Before the first setup, start your normal DCS installation once. Exit DCS through its normal menu. Keep DCS closed for setup. The first setup reads settings from your normal DCS profile. Before setup, copy that profile to a separate backup folder outside Saved Games and the application folder. Keep the original profile in place. Check that the backup contains your Config, Scripts, and any personal missions. Data safety explains what the application changes and what the backup protects. Run setup and flights as a normal user; only the documented firewall/driver tasks need administrator rights.

  1. Enter this command:
.\dcs-tablet.exe setup
  1. Wait for Setup complete.

Result: DCS Tablet creates a separate profile named DCS.Tablet. It copies your initial graphics settings and controller settings. It adds the DDI display settings and the DDI control connection. Your normal DCS profile remains separate. The DCS installation files are not modified. Later changes to your normal profile do not update DCS.Tablet automatically.

The application does not copy missions, aircraft modifications, or other export scripts. DCS can ask for your account details when you first use the new profile.

If setup cannot find DCS, use the command examples. If setup finds more than one virtual display, use the display selection example on that page.

8. Start an F-18 flight

Before you start, make sure that the demo has stopped. Keep the virtual display available to Windows. The application activates that display when necessary.

  1. Close the setup PowerShell window.
  2. Double-click Start-DCS-Tablet.cmd.
  3. Keep the application console open.
  4. Wait for DCS World to open.
  5. Start a mission with the F/A-18C Hornet.
  6. Switch on the aircraft DDIs.
  7. Open the application address on the tablet.
  8. Tap Connect.
  9. Wait for Touch controls ready.

Result: The tablet shows the left and right aircraft DDIs. A touch button operates the corresponding aircraft button.

For the first check, use a powered aircraft in a training mission. A dark aircraft display can give a dark tablet display.

Do not minimize the DCS window during a flight. Do not move another window over the virtual display's DDI areas. The tablet shows the pixels in those areas.

9. Use the tablet controls

Task Action
Show only the left DDI Tap the left display image.
Show only the right DDI Tap the right display image.
Show both DDIs Tap Both DDIs.
Operate an aircraft button Tap its button around the display.
Increase image brightness Tap + beside DDI brightness.
Decrease image brightness Tap − beside DDI brightness.
Hide the application header Tap Full screen.
Show the application header Tap Exit full screen.
End the tablet connection Tap Disconnect.

The brightness control changes only the tablet image. It does not change the aircraft's brightness setting. The browser can keep some browser controls visible in full screen.

A continuous button press has a two-second limit. Release the button before another press. Keep the tablet in landscape position.

10. End a flight

  1. Tap Disconnect on the tablet.
  2. Exit DCS World through its normal exit menu.
  3. Wait for the DCS Tablet console to finish.
  4. If the console asks for a key, press Enter.

Result: DCS Tablet stops its video service. It returns the virtual display to its previous state.

If the virtual display was inactive before the flight, it becomes inactive again. If it was active, it can remain active.

If the application stops unexpectedly, use Recovery and removal.

Network connection

Complete this task before the demo's first connection. DCS Tablet permits one connected viewer at a time.

Before you start

Use a private network with devices that you trust. Do not use public Wi-Fi for DCS Tablet. Do not use a guest network that prevents communication between devices.

DCS Tablet has no password or tablet approval step. A reachable device can request the video connection. The active viewer can also operate the DDI buttons during a flight.

The page and control messages use HTTP without encryption. WebRTC encrypts the video connection. These protections do not identify the person who connects.

1. Set the Windows network profile

Before you change the profile, make sure that you trust the network and its devices.

  1. Open Windows Settings.
  2. Open Network & internet.
  3. For Wi-Fi, open the connected Wi-Fi network's properties.
  4. For a cable connection, open Ethernet.
  5. Set Network profile type to Private.

Result: Windows identifies your connection as a private network. Windows labels can be different between versions. Microsoft's network instructions show the current controls.

2. Open Administrator PowerShell

This task adds a Windows Firewall rule. Normal flights do not need Administrator PowerShell.

The commands below assume that the application folder is DCS Tablet on your desktop.

  1. Open the Windows Start menu.
  2. Enter PowerShell in the search field.
  3. Right-click Windows PowerShell.
  4. Click Run as administrator.
  5. If Windows asks for approval, click Yes.
  6. Enter this command:
Set-Location -LiteralPath (Join-Path ([Environment]::GetFolderPath('Desktop')) 'DCS Tablet')

Result: Administrator PowerShell uses the application folder. If your application folder is elsewhere, use its full folder path instead.

Example:

Set-Location -LiteralPath 'D:\Flight Tools\DCS Tablet'

3. Add the firewall rule

  1. Enter this command in Administrator PowerShell:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Allow-Private-Network.ps1 -ExecutablePath "$PWD\dcs-tablet.exe"
  1. Wait for Private local-subnet access enabled.
  2. Close Administrator PowerShell.

Result: The rule permits nearby network devices to reach this application on private networks. It does not permit all Windows applications.

The execution policy option applies only to the PowerShell process that executes this command. It does not change the saved Windows script policy.

Repeat this task if you move dcs-tablet.exe to another folder. The firewall rule contains the application file's full path. Do not turn off Windows Firewall.

4. Find the correct PC address

The demo console shows a LAN: address. A VPN or virtual network adapter can cause an incorrect address.

If necessary, find the address as follows:

  1. Open a normal PowerShell window.
  2. Enter this command:
ipconfig
  1. Find the active Wi-Fi or Ethernet adapter.
  2. Find its IPv4 Address.
  3. Add that address between http:// and :8090/ in the tablet browser.

Example:

PC IPv4 Address: 192.168.1.20
Tablet address:  http://192.168.1.20:8090/

The tablet cannot use the PC's 127.0.0.1 address. That address refers to the device on which you enter it. The tablet browser needs the PC's network address.

During use

Keep the tablet page visible. If the tablet stops the browser in the background, return to the page. Tap Connect again if necessary.

The browser can prevent automatic screen locking on some devices. If necessary, change the tablet's automatic screen-lock setting for the flight.

Connection limits

DCS Tablet closes incomplete request headers after two seconds. It closes incomplete request bodies after three seconds. These limits prevent slow requests from holding application workers. They do not add authentication or HTTP encryption.

Next task

Continue with the demo. If the page does not open, use the problem guide.

Virtual display

A virtual display is an extra Windows screen without a physical monitor. DCS uses this screen to draw both DDIs outside your physical screen. DCS Tablet then sends those images to the tablet.

The virtual display must be active during a flight. Space outside all active Windows displays does not contain an image that the application can capture.

Required settings

Setting Required value
Virtual display size 1024 × 512 pixels
Position during a flight Immediately right of the main display
Display arrangement Extend
Main display Your physical monitor
HDR Off on the virtual display

Example arrangement:

Physical monitor              Virtual display
+-------------------------+   +-------------------+
|                         |   | Left DDI | Right  |
|     DCS cockpit         |   | 512x512  | DDI    |
|                         |   |         | 512x512|
+-------------------------+   +-------------------+
Visible on your desk          Extra drawing space

For a 1920 × 1080 physical monitor, the complete DCS image is 2944 × 1080 pixels. The cockpit still uses the physical monitor's area. The tablet receives the two DDI areas.

1. Install the driver

Before you start, close DCS World. If the driver is already installed, continue with task 2.

  1. Open the Virtual Display Driver release page.
  2. Get the installer identified in the driver's instructions.
  3. Open the installer.
  4. Follow its installation instructions.
  5. If Windows asks for administrator approval, check the file's source before you continue.
  6. If the source is correct, click Yes.

Result: Windows has an extra virtual display adapter. The driver instructions identify its installation controls. DCS Tablet does not include or install the driver.

2. Check the display mode

  1. Open Windows Settings.
  2. Open System > Display.
  3. Click Identify.
  4. Select the virtual display's numbered rectangle.
  5. Set its display arrangement to Extend.
  6. Select 1024 × 512 in Display resolution.
  7. If Windows asks to keep the change, click Keep changes.
  8. Set HDR to Off for this display.
  9. Make sure that your physical monitor remains the main display.

Result: The virtual display has the required size. If 1024 × 512 is unavailable, complete task 3. Otherwise, continue with task 4.

3. Add the missing display mode

Use this task only if the driver's settings do not offer 1024 × 512. It adds one resolution to the driver's existing configuration file.

The usual file is C:\VirtualDisplayDriver\vdd_settings.xml. If this file is absent, use the location specified by the driver's documentation. Do not create a replacement file in an unrelated folder.

  1. Open the configuration file's folder in File Explorer.
  2. Select vdd_settings.xml.
  3. Press Ctrl+C.
  4. Press Ctrl+V to make a backup copy.
  5. Open the Windows Start menu.
  6. Enter Notepad in the search field.
  7. Right-click Notepad.
  8. Click Run as administrator.
  9. Click File > Open in Notepad.
  10. Enter the original configuration file's full path in File name.
  11. Click Open.
  12. Find the closing line </resolutions>.
  13. Add the following entry immediately before that closing line:
<resolution>
  <width>1024</width>
  <height>512</height>
  <refresh_rate>60</refresh_rate>
</resolution>
  1. Keep the other entries in the file.
  2. Save the file.
  3. Close Notepad.
  4. Save your work in other applications.
  5. Restart Windows.
  6. Repeat task 2.

Result: Windows offers 1024 × 512 for the virtual display.

The driver configuration example shows the XML structure. The example above is an entry, not a complete configuration file.

4. Prepare for automatic restoration

The application records the virtual display's state before each flight. It restores that state after DCS closes.

If you want the virtual display inactive between flights:

  1. Select only the virtual display in Windows Display settings.
  2. Select Disconnect this display.
  3. If Windows asks to keep the change, click Keep changes.

Result: The driver remains installed, but the virtual display is inactive. DCS Tablet activates it when you start a flight.

Do not disconnect your physical monitor. The Windows control can have a different name in another Windows version.

More than one virtual display

DCS Tablet selects a virtual display automatically when it finds only one. If it finds more than one, use the display selection example.

The application places its selected display to the right of the main display. Another active monitor must not occupy the same area.

During a flight

Keep the DCS window visible. Do not cover the DDI areas with other windows. The application captures those screen areas, including another window that covers them.

Next task

Continue with DCS profile setup. For an unexpected stop, use Recovery and removal.

Problem guide

Use the procedure for the symptom that you see. The application initially supports only the DCS F/A-18C Hornet.

The application does not open

If Windows reports that VCRUNTIME140.dll is missing:

  1. Open Microsoft's runtime download instructions.
  2. Download the Visual C++ v14 x64 Redistributable from Microsoft.
  3. Run its installer.
  4. Start DCS Tablet again.

Result: Windows can load the application's native runtime. Do not download individual DLL files from unofficial websites.

The Windows H.264 encoder is unavailable

  1. Make sure that you use Windows 10 or Windows 11.
  2. On a Windows N edition, install the Media Feature Pack.
  3. Restart Windows if the feature installer requests it.
  4. Start the demo again.

Result: The demo uses the H.264 encoder supplied by Windows. The application does not download an alternative codec.

The tablet page does not open

  1. Make sure that the application console is open on the PC.
  2. Make sure that the tablet uses the same network as the PC.
  3. Compare the browser address with the PC's active IPv4 address.
  4. Include http:// and :8090/ in the address.
  5. Complete the network connection tasks.
  6. Open the address again.

Result: The DCS Tablet page opens.

Example of a complete address:

http://192.168.1.20:8090/

If a VPN changes the selected address, use the Wi-Fi or Ethernet address instead. A guest network can prevent the connection even when both devices have Internet access.

The page opens, but video does not start

  1. Tap Disconnect on any other device that uses DCS Tablet.
  2. Tap Connect on the intended tablet.
  3. If video remains absent, check the firewall rule.
  4. If necessary, do the demo test again.

Result: The intended tablet shows moving images.

The firewall rule must permit this application file. A rule for only TCP port 8090 can permit the page but prevent video. The supplied firewall script also permits the video traffic.

The page shows DEMO instead of the aircraft

  1. Stop the demo as given in the user guide.
  2. Double-click Start-DCS-Tablet.cmd.
  3. Start an F/A-18C mission.
  4. Tap Connect on the tablet.

Result: The page shows the aircraft's DDI images.

The aircraft displays are dark

  1. Make sure that the mission uses the F/A-18C Hornet.
  2. Make sure that the aircraft has electrical power.
  3. Switch on both aircraft DDIs.
  4. Make sure that the DCS window is not minimized.
  5. Make sure that another window does not cover the virtual display's DDI areas.

Result: The tablet also shows the powered aircraft display.

If both images remain dark, close DCS normally. Use the recovery procedure before another attempt.

The touch buttons do not operate

  1. Make sure that the mission uses the F/A-18C Hornet.
  2. Make sure that you started DCS through Start-DCS-Tablet.cmd.
  3. Wait for Touch controls ready on the tablet.
  4. Release all tablet buttons.
  5. Tap one DDI button again.

Result: The corresponding aircraft button operates.

The demo does not operate aircraft buttons. A continuous press stops after two seconds. A lost connection also causes the application to release held buttons.

Video works, but touch controls become unavailable

Video and touch controls use separate connections. A control status change does not necessarily mean that video has disconnected.

  1. Use version 0.1.1 or later.
  2. If necessary, exit DCS normally before you replace the application files.
  3. Start the updated application through Start-DCS-Tablet.cmd.
  4. Reload the tablet page.
  5. Tap Connect.

Result: Touch controls ready remains visible during normal Hornet operation.

Early development builds could delay control acknowledgements after a pause. Current releases drain old replies to avoid this backlog. DCS controls unavailable · waiting for a reply identifies an unavailable control connection. Start a Hornet mission for touch controls identifies a responding connection without an active Hornet.

Setup cannot find DCS

  1. Find DCS.exe in your DCS installation folder.
  2. Use the DCS location example.

Result: Setup finds the application file and creates the separate profile.

Setup cannot find the source profile

A source profile contains your normal DCS settings. Its usual folder is Saved Games\DCS. Some installations use DCS.openbeta or another folder name.

  1. Start your normal DCS installation once.
  2. Exit DCS normally.
  3. Find the profile folder that contains Config\options.lua.
  4. Use the source profile example.

Result: Setup copies the correct initial settings.

Setup finds more than one virtual display

  1. Use the display selection example.

Result: Setup uses only the display that you selected.

The console says that port 8090 is in use

  1. Stop any previous DCS Tablet demo.
  2. Close any previous DCS Tablet flight normally.
  3. Start the intended session again.

Result: One DCS Tablet session uses the address.

If another application needs that port, use the port example. Do not stop an unknown Windows process.

The console requests display recovery

  1. Close DCS World.
  2. Double-click Restore-Display.cmd.
  3. Read the result in the console.

Result: The application restores the previous virtual display state. If restoration stops, use Recovery and removal.

The tablet requests landscape position

  1. Hold the tablet with its long side horizontal.
  2. If necessary, release the tablet's rotation lock.

Result: The page removes the rotation message. Use landscape position with this version.

The image stops after the tablet locks

  1. Unlock the tablet.
  2. Return to the DCS Tablet page.
  3. Tap Connect if necessary.

Result: The live images continue. The tablet can stop its browser when the page is not visible.

Collect information for help

Before you collect the report, close the DCS Tablet flight console. The doctor command cannot use the session lock while a managed flight is active.

  1. Open PowerShell in the application folder.
  2. Enter this command:
.\dcs-tablet.exe doctor
  1. Record the version and build date.
  2. Copy the exact error message.
  3. Describe the last action before the problem.
  4. Remove personal details before you share the report.

The report can include your Windows user name or folder paths. The local log folder is %LOCALAPPDATA%\DCS Tablet. Command examples explain how to open that folder.

Setup or removal refuses a linked path

Do not replace the managed DCS.Tablet folders or files with junctions, symbolic links, or hard links. The application requires independent writable copies and refuses links to protect the normal profile. Leave all folders intact. Use an ordinary copied source profile if your original input setup uses linked directories. Do not edit the ownership manifest or delete the original profile to bypass this check. See Data safety and Recovery and removal.

Recovery and removal

Display recovery returns the virtual display to its previous state. Profile removal preserves the complete profile in an archive. Application removal is a separate task.

Restore the display

Use this task after an unexpected stop or a request for recovery.

  1. Close DCS World.
  2. Open the application folder.
  3. Double-click Restore-Display.cmd.
  4. Read the console message.
  5. If the console asks for a key, press Enter.

Result: The console reports restoration or No display recovery pending.

Do not delete display-recovery.json before restoration is complete. This file contains the display state that the application must restore.

If automatic restoration stops

A different display arrangement can prevent automatic restoration. The application stops rather than replace a new arrangement.

  1. Close DCS World.
  2. Open Windows Settings > System > Display.
  3. Identify the physical monitor and the virtual display.
  4. Make sure that the physical monitor is the main display.
  5. Return the virtual display to its previous state.
  6. Double-click Restore-Display.cmd again.
  7. If the warning continues, keep the recovery file for technical support.

Result: Your physical monitor operates in its normal arrangement.

If necessary, move a window back from the virtual display with Windows+Shift+Left Arrow. The required arrow key depends on the display arrangement.

Remove the DCS Tablet profile

Before you start, complete display recovery and close DCS World.

  1. Open PowerShell in the application folder.
  2. Enter this command:
.\dcs-tablet.exe uninstall-profile
  1. Read and keep the printed backup path.

Result: The application renames the complete DCS.Tablet folder into a backup beside it. The name begins with DCS.Tablet.backup- and has a unique suffix. No profile files are deleted. Edited controller bindings, missions, login files, and DCS-generated files stay in the archive. The move stays on the same volume, so it does not need space for a second full copy. A later setup creates a new independent DCS.Tablet profile.

Keep this archive until you have checked that everything you need is present. It can contain account/login data: do not upload it publicly or include it in a support report. An archive on the same drive is not protection against drive failure; keep a separate backup of important personal files.

The application refuses unowned profiles, invalid records, and linked managed paths. If it refuses removal, leave the folder intact. Do not delete files, edit the ownership record, or force the operation. For a manual fallback, close DCS and rename only the actual DCS.Tablet folder to an unused backup name in File Explorer. Never merge with or replace an existing backup. Do not change your normal DCS or DCS.openbeta folders. If you are unsure which folder is the dedicated profile, stop and request help.

Remove the firewall rule

  1. Open Administrator PowerShell as given in Network connection.
  2. Enter this command from the application folder:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Allow-Private-Network.ps1 -Remove
  1. Close Administrator PowerShell.

Result: Windows removes the DCS Tablet private LAN rule.

Remove the application

  1. Make sure that DCS Tablet has stopped.
  2. Keep any local logs that you need.
  3. Delete the extracted application folder.
  4. If you no longer need its settings, delete %LOCALAPPDATA%\DCS Tablet.

Result: The application and its selected local settings are absent.

The virtual display driver is a separate application component. If no other application needs it, use the driver's own removal instructions. Do not delete driver files manually.

Data safety

DCS Tablet uses a separate profile and does not install files into DCS World. This page describes the protection boundaries. It is not a guarantee against drive failure, interrupted writes, or changes made by other software.

Before setup

  1. Exit DCS normally.
  2. Copy your normal Saved Games profile (DCS or DCS.openbeta) to a separate backup folder outside Saved Games and the application folder.
  3. Check that you can open the copy and that it contains your Config, Scripts, and personal missions.
  4. Keep the original profile in place. Do not move or delete it.

If you have irreplaceable missions or controller settings, keep a backup on another drive too. Run setup and flights without administrator privileges. Driver installation and the documented firewall task are the separate exceptions.

What the application changes

Location Operation
DCS World installation Reads/starts DCS.exe; no installation files are rewritten or removed.
Normal Saved Games profile Reads initial graphics settings and input bindings; does not rewrite them.
Saved Games/DCS.Tablet Creates an independent profile and its ownership record; upgrades only unchanged owned bridge content.
LocalAppData/DCS Tablet Saves application settings, capture configuration, logs, lock, and display recovery data.
Selected virtual display Temporarily enables/positions it; restores its recorded state after normal DCS exit.
Windows Firewall The separate administrator script adds/removes only the named program-specific private-LAN rule.

Setup refuses an existing unowned DCS.Tablet folder and claims new profile directories exclusively. The Saved Games override must resolve to the real Windows Saved Games folder, not a game installation or a profile subfolder. Managed profile paths must not contain junctions, symbolic links, or shared hard-linked files. This prevents a shared configuration path from redirecting modifications into another profile. Use independent copies rather than linking DCS.Tablet to the normal profile.

Removal preserves the profile

In version 0.1.1, uninstall-profile archives the whole profile to a unique DCS.Tablet.backup-* sibling folder. It does not delete its files. User edits, missions, bindings, credentials, and generated files stay together. An existing backup is never replaced. Keep the printed path and inspect the archive before deciding what you no longer need. Do not upload this archive: it can contain account information. A same-drive archive is not a second independent copy and does not protect against a failed drive.

If automatic removal refuses a path or manifest, leave the data intact and use the non-destructive guidance in Recovery and removal. Do not delete the normal DCS profile or force removal by editing the manifest.

Display and driver recovery

Keep the launcher console open during a flight. Exit DCS normally so it can restore the virtual display. After an interruption, close DCS and run Restore-Display.cmd. Keep display-recovery.json until restoration is verified. The application retains that record when recovery cannot safely complete. A new or overlapping display arrangement requires manual review rather than being overwritten.

Before installing/configuring a third-party virtual display driver, record your current Windows display layout and back up its settings file as described in Virtual display. The driver is installed separately and can affect Windows independently of DCS Tablet. Avoid changing monitor arrangements while the managed session is active.

What is tested

Temporary fixtures exercise ownership rejection, linked profile/input folders, shared files, temporary-file collisions, existing backup destinations, interrupted setup, and archival of edited/personal files. Tests compare file contents before and after operations; your real profile is not used for destructive tests. Hardware checks and live cockpit results are recorded separately in Test record.

Technical description

This page is for developers and technical support. The user guide contains the operating instructions.

The first aircraft for this application is the DCS F/A-18C Hornet only. Aircraft button mappings are specific to that module.

Application components

DCS Tablet is one native Windows Rust application. The executable includes its browser page and Lua script. It uses operating-system threads without a Rust async runtime.

Component Function
Windows Graphics Capture Reads the selected display's pixels.
Windows Media Foundation Encodes the DDI images with the Microsoft H.264 transform.
str0m Provides the WebRTC video connection.
httparse Parses HTTP request headers.
Windows APIs Control display state and window position.
Lua script Operates the aircraft's DDI buttons.

Video path

DCS DDI exports
    -> Active virtual display
    -> Windows Graphics Capture
    -> Windows Media Foundation H.264 encoder
    -> WebRTC connection
    -> Tablet video decoder
    -> Left and right display images

The default combined image is 1024 × 512 pixels at 30 frames per second. The target bit rate is 1 Mbit/s. The H.264 configuration uses the existing Level 3.1 limits.

Capture and encoding operate only while a video viewer is active. New raw frames replace old raw frames in storage. Encoded frames use a four-frame FIFO. Overflow clears dependent output and requests a fresh keyframe before sending resumes. Video queues and diagnostic histories have fixed limits. The capture check compares the Windows device identity with the selected display.

Control path

The browser sends ordered button-state messages to /controls. Each DDI uses a 20-bit button mask. The Rust control worker sends messages to the Lua script through loopback UDP.

The Lua script listens at 127.0.0.1:17881. It operates only inside the DCS.Tablet profile. It accepts a fixed message format rather than executable Lua text.

Mapping Value
Left DDI device 35
Right DDI device 36
Button commands 3011 through 3030
Press value 1
Release value 0

Both sides reject old message revisions. Lost contact causes button release. A continuous button press has a two-second limit. These checks do not authenticate a user.

HTTP limits

One nonblocking I/O thread manages the HTTP sockets. Four application workers receive only complete requests.

Limit Value
Active connections 32
Connections per source IP 8
Remote connection slots 28
Slots reserved for loopback connections 4
Complete request queue 16
Header size 8 KiB
Header fields 64
Header deadline 2 seconds
Body deadline after complete headers 3 seconds
Response write deadline 2 seconds
Application response deadline 10 seconds
Offer body size 64 KiB
Control body size 512 bytes

Slow progress does not extend these deadlines. Other routes accept no body. The application accepts fixed Content-Length bodies. It rejects Transfer-Encoding, upgrades, Expect, duplicate Content-Length, and pipelining. Each response closes its connection.

A full work queue gives HTTP 503. Excess connections close immediately. Shutdown closes incomplete input and gives computed responses a maximum 100-millisecond flush interval.

Managed flights

The launcher starts a separate streamer process and DCS. It checks the streamer process identity and HTTP health. It permits three recovery attempts in a 60-second interval. After a streamer restart, the tablet must connect again.

The launcher records the display state before a change. Updates to JSON records use unique, exclusively created temporary files, synchronized contents, and atomic replacement. A first-time write cannot replace a newly appearing unrelated destination. An exclusive session lock prevents simultaneous managed operations. Recovery waits until DCS has closed.

DCS profile protection

The separate profile contains initial copies of options and controller settings. It does not share writable junctions with the source profile. Removal validates ownership and managed paths, then archives the whole profile by a nonreplacing directory move. No profile contents are deleted, including user-edited and DCS-created files. Managed paths reject reparse points and shared hard-linked files.

Build information

build.rs calculates a build ID from source files, build metadata, browser content, Lua content, and enabled features. The UTC build date uses compile-time information. SOURCE_DATE_EPOCH can supply a fixed timestamp for a release build. The build ID is diagnostic information, not a signature.

Windows encoder lifecycle

The encoder worker initializes COM and Media Foundation on its own thread. It uses the synchronous Microsoft H.264 encoder with Baseline profile and Level 3.1. BGRA images are converted to limited-range BT.601 NV12 before encoding. The encoder uses low-latency mode without B-frame reordering. Requested keyframes contain the sequence and picture parameter sets required by WebRTC. The worker releases COM objects before it shuts down Media Foundation. Windows supplies the encoder; DCS Tablet does not redistribute codec implementation files.

Failure and ownership contracts

The control protocol defines viewer sessions, revisions, UDP retries, and release timers. A video session owns its capture source and encoder worker. Cancellation wakes pacing waits before joins. The encoder initializes COM and Media Foundation on its own thread. Its interfaces are released before that runtime shuts down. Media Foundation timestamps use 100-nanosecond units; RTP video uses a 90-kHz clock. Display coordinates are physical desktop pixels; the generated DCS monitor layout uses window-relative export coordinates.

Capture freshness is separate from HTTP liveness. The page warns after eight seconds without a source callback; it does not restart static content. Managed profile schema 2 upgrades an unchanged owned bridge atomically. User-edited files stop the upgrade. Options and input bindings remain independent user copies. A monitor-layout resolution change still requires profile reinstallation. The old ownership manifest remains until the bridge write succeeds, so an interrupted upgrade can accept either complete version. Settings and display recovery use typed schema validation before persistent values are applied.

Build and diagnostics

--build-info prints machine-readable build metadata. --verify-source PATH verifies the source/feature fingerprint. This fingerprint identifies accidental mismatches; it is not a cryptographic signature. Packaging rejects test-hook binaries, the wrong target, mismatched source/dependency files, and an out-of-date offline guide. Each package contains BUILD-INFO.json. The launcher owns piped streamer output and rotates stream.log after two MiB, retaining at most three prior logs. Rotation also occurs during an active session. Each new log is limited to two MiB; session boundaries include a timestamp and build ID. A peer UDP reset is logged as a transport departure; encoder and capture errors remain pipeline failures.

The data-safety contract describes write boundaries, backups, and recovery limits.

Control protocol and ownership

This document explains the browser, Rust worker, and Lua bridge contract. The messages describe button state, not commands to execute arbitrary Lua. The protocol is local to the PC and is not authentication.

Browser to Rust

POST /controls carries JSON with integer session, revision, left, and right fields. Each mask has 20 bits. Bit zero represents pushbutton 1; bit 19 represents pushbutton 20. The server accepts only the current viewer's IP and session, increasing nonzero revisions, and masks no larger than 1048575. HTTP 202 means queued, not that DCS has acknowledged the action. The queue holds at most 64 snapshots.

A browser connection generation owns its status requests and control pump. Disconnect invalidates that generation and aborts pending requests. Replies from an older generation cannot change the current viewer's state. Status polling is single-flight and times out after five seconds. A control request times out after 1.5 seconds.

Held inputs publish snapshots every 150 milliseconds. Pointer cancellation, hiding the page, losing focus, changing views, and disconnect release held inputs. A release beacon can outlive the page; the server's revision check rejects an earlier request that arrives after that release. Reconnecting starts a new control session and resets browser revisions.

Rust to Lua

The Lua bridge listens on 127.0.0.1:17881 inside the dedicated DCS.Tablet profile. The Rust worker owns one connected loopback UDP socket and polls every 20 milliseconds.

Idle probe:      HDDI1 PING
Idle reply:      HDDI1 PONG READY
                HDDI1 PONG WAIT
State snapshot: HDDI1 <epoch> <serial> <left-mask> <right-mask>
Acknowledgment: HDDI1 <epoch> <serial> READY
                HDDI1 <epoch> <serial> WAIT

READY means the current aircraft is the supported F/A-18C; WAIT means it is not. The worker epoch identifies a worker lifetime and is independent of the browser session. The serial advances for changed snapshots and session-release handshakes. Rust retries the current snapshot until its matching acknowledgement arrives. Lua acknowledges duplicate serials without applying the same press again. Old serials are ignored. A different epoch or source port must first send both masks released before becoming owner.

Rust drains up to 256 pending replies per polling cycle. This prevents stale duplicate replies from delaying a new acknowledgement after DCS resumes. Lua reads at most 32 packets per frame so networking cannot monopolize the simulation callback.

Release limits

Rust considers acknowledgements fresh for 700 milliseconds. A stale acknowledgement disables new input independently of the video connection. Lua releases held buttons after 750 milliseconds without a valid state packet. Lua also ends a continuous hold after two seconds, even with fresh heartbeats. An expired hold is blocked until a released mask rearms that button. Lua cleanup runs on aircraft changes and export shutdown, and preserves prior export callbacks.

These timers serve different purposes; increasing the browser HTTP timeout does not extend the Lua hold limit. A DCS simulation stall can prevent callbacks and temporarily interrupt readiness. The watchdogs favor releasing controls over preserving a stuck press.

Documentation writing guide

Use ASD-STE100 Simplified Technical English, Issue 9, for this documentation. The official specification gives the writing rules and dictionary.

Writing rules

  1. Give one instruction in each procedural sentence.
  2. Keep procedural sentences within 20 words.
  3. Keep descriptive sentences within 25 words.
  4. Use the active voice.
  5. Put a necessary condition before its instruction.
  6. Use the same term for the same item.
  7. Define an abbreviation before unfamiliar use.
  8. Give a result after a task.
  9. Use notes only for information.
  10. Check each word's meaning and part of speech against the dictionary.

Sentence length alone does not establish STE conformity. A reviewer must also check word meanings, technical terms, grammar, and task accuracy. The project does not claim independent STE certification.

Version history

Initial aircraft support is for the DCS F/A-18C Hornet only. Basic live cockpit video and touch controls have been checked. Extended tablet and complete managed flight tests are still necessary.

Version 0.1.1 — profile and data safety

Profile removal now archives the entire dedicated profile without deleting files. Edited bindings, missions, credentials, and generated files remain in the backup. Managed paths reject junctions, symbolic links, and shared hard-linked files. Setup exclusively creates a new profile and verifies the actual Windows Saved Games location. Atomic state writes use unique, exclusively created temporary files and synchronized contents. Backup moves never replace an existing destination. Display recovery checks for overlaps and verifies the restored state before deleting its record. The instructions add a pre-setup backup and remove destructive profile-removal advice.

Version 0.1.0

Reliability and maintainability review

Browser status and control requests are isolated between connection generations. Playback failures now enable retry. Encoded-frame overflow requests a fresh keyframe. Capture freshness is reported separately from service availability. Setup upgrades an unchanged managed bridge while preserving user edits. Saved settings, profile manifests, and display recovery records have typed schema validation. Packaging checks the source fingerprint, target, production features, and generated guide. Fault injection, browser recovery regressions, package guards, and Lua tests are included in CI. Source documentation explains ownership and protocol invariants; browser/Lua formatting is readable. Logs rotate during sessions and identify their build.

Windows encoder and documentation

Windows Media Foundation now provides H.264 encoding. The application no longer builds or distributes OpenH264. The browser protocol remains H.264 over WebRTC. The documentation identifies the Visual C++ runtime and Windows N media feature requirements. The source includes the offline-guide generator and its pinned documentation dependency.

Control connection correction

The control connection now drains queued UDP replies before the next polling cycle. Old replies no longer delay acknowledgement of a new button press or release. The page distinguishes an unavailable DCS control connection from a mission that has not started. The status response includes control acknowledgement age for diagnostics.

HTTP service improvements

The HTTP service now receives complete requests before it gives them to application workers. Slow request headers and bodies have fixed time limits. Connection counts and request queues have fixed capacity limits. Health checks and shutdown continue while requests remain incomplete.

The HTTP layer now uses httparse instead of tiny_http. Six network regression scenarios check the availability protections. The Windows workflow includes these tests.
